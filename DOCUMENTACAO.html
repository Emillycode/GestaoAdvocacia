1. Visão Geral da Arquitetura

O sistema "Gestão Advogados" foi projetado utilizando a arquitetura MVC (Model-View-Controller) em PHP puro. Ele utiliza o SQLite como banco de dados principal pela sua facilidade de portabilidade (dispensa configuração de servidores MySQL).

A arquitetura se divide da seguinte forma:

  • /app/controllers/: Contém a lógica de negócio (CRUDs, autenticação).
  • /app/views/: Contém as interfaces (HTML, Bootstrap 5).
  • /db/: Armazena o banco de dados database.sqlite.
  • /public/: Arquivos públicos como imagens (favicon) e uploads de documentos.
  • index.php: Atua como Front Controller, roteando todas as requisições do sistema.
  • config.php: Arquivo central de configurações e conexão PDO.

2. Isolamento de Contas (Multi-Tenant)

O sistema foi atualizado para uma arquitetura Multi-Tenant. Isso significa que todos os dados gravados no banco de dados estão atrelados ao usuario_id (identificação do e-mail que fez o login). Um advogado logado como A não tem acesso aos processos, clientes ou documentos do advogado B.

Regra de implementação futura: Qualquer nova tabela ou funcionalidade que guarde dados sensíveis deve possuir uma coluna usuario_id, e as queries SQL (SELECT, UPDATE, DELETE) devem obrigatoriamente validar essa coluna via parâmetro na sessão (\['user_id']).

3. Autenticação e Segurança (2FA)

A segurança é reforçada por uma verificação de duas etapas:

  • Senha Mestre: Validada primeiro no controlador AuthController (ex: Adm@2026).
  • Envio SMTP: Após a senha mestre ser digitada, um código de 6 dígitos é gerado aleatoriamente e enviado ao e-mail informado no input.
  • Sessão: O usuário só é considerado isLoggedIn() === true após confirmar o código, ganhando um \['user_id'] gerado a partir do seu e-mail.

4. Estrutura de Banco de Dados

O sistema utiliza as seguintes tabelas no arquivo database.sqlite:

  • usuarios: Armazena o e-mail, id único e os códigos temporários do 2FA.
  • clientes: Cadastro base (Nome, e-mail, telefone, CPF).
  • processos: Detalhes processuais (Número, Tribunal, Vara, andamento e status). Relacionado à tabela clientes.
  • prazos: Agenda de compromissos e audiências.
  • financeiro: Controle de despesas e receitas.
  • documentos: Armazenamento do caminho lógico dos arquivos upados.

5. Integração com WhatsApp (API Externa)

Ao editar o Andamento Resumido de um processo na aba Processos, o ProcessoController.php monta automaticamente uma URL de redirecionamento do wa.me (WhatsApp Web/App) contendo uma mensagem pré-formatada com o nome do cliente, número do processo e o andamento digitado.

6. Como realizar atualizações futuras

Se um novo desenvolvedor for adicionar recursos, siga estas diretrizes:

  1. Criar a Rota: Adicione a nova URL no switch(\) do index.php.
  2. Criar o Controller: Adicione um arquivo NomeController.php em /app/controllers/.
  3. Sempre Validar Usuário: Todas as queries devem incluir WHERE usuario_id = ?, usando a variável global de sessão.
  4. Uploads: Arquivos upados devem ser isolados; caso adicione um módulo de upload, grave o nome criptografado para evitar colisões no disco.
